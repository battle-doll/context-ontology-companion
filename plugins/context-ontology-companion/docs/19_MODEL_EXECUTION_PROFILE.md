# 19. Astra Pro를 활용하는 개발·검토 프로필

상태: 모델 비종속 실행 정책. 제품 runtime 모델 설정이 아닙니다.

## 고정하지 않을 것

Astra라는 이름으로 컨텍스트 창, 토큰 예산, API 식별자, 도구 권한 또는 subagent 선택 가능성을 가정하지 않습니다. 실제 호스트가 보여준 모델/권한/도구만 기록합니다. Chat에서 사용 가능하다고 Codex에서도 동일 옵션을 선택할 수 있다고 간주하지 않습니다. 구독과 API 비용도 별개로 확인합니다.

## 역할 배치 제안

| 역할 | 산출물 | 배치 원칙 |
| --- | --- | --- |
| Orchestrator | 작업 분할, 의존성, 상태·비용, 최종 보고 | 가능한 가장 단순한 실행 제어; 설계 권위 자동 부여 금지 |
| Architect | ADR, 계약, 대안 비교, 실패 조건 | 복잡한 범위에는 Astra Pro 우선 후보 |
| Implementer | 한정된 변경과 재현 가능한 시험 | 실제 코딩 성능·비용을 보고 모델 결정 |
| Adversarial reviewer | 반례, 불변식 위반, 삭제/권한/시점 위험 | 가능하면 별도 문맥/인스턴스; 실재 여부 명시 |
| Deterministic checks | JSON Schema, 타입, fixtures, unit/integration test | 모델 의견이 아니라 실행 결과로 판정 |

모든 작업을 가장 비싼 추론 설정으로 처리하거나 검토 루프를 무한 반복하지 않습니다. 반복 제한/비용 예산은 현재 환경에서 가용한 수치로 정하고, 새 근거 없는 재검토는 중단합니다. 임계값은 정책 파일로 관리하되 플랫폼 설정 키를 임의로 발명하지 않습니다.

## 한 작업의 입력

목표, 변경 허용 경로, 반드시 지킬 제약, 관련 ADR/근거, 현재 코드 리비전, 완료 시험, 예산과 승인 경계를 제공합니다. 모든 문서/과거 대화를 매번 주입하지 않습니다. 모델에는 결론·간단한 설계 근거·반례·시험을 요구하며 내부 추론 전문을 저장하지 않습니다.

## 검토 순서

첫 패스에서 가장 작은 작동 경로를 설계합니다. 두 번째 패스에서는 설계가 틀릴 수 있는 사례를 찾습니다. 구현 후에는 실제 시험과 diff로 검토합니다. 별도 에이전트가 없으면 '한 에이전트의 분리된 검토 패스'로 기록합니다. 자기 검토를 독립 보안 감사라고 쓰지 않습니다.

## 이번 검토에서 확인 가능한 것

사용자가 앞선 대화를 Sol Pro, 현재를 Astra Pro라고 설명했습니다. 공식 문서는 Astra/GPT-6 Pro의 제품별 제공과 사용량 차이를 설명합니다. 그러나 이번 문서 작업은 두 모델에 동일 시험을 돌린 비교 실험이 아닙니다. 모델 전환 때문에 개선 효과가 얼마인지 숫자로 주장하지 않습니다.

## 첫 개발 결과의 기대 형태

P0 보고서, 수정 ADR, 최소 draft 계약, 합성 결정 하나를 저장·조회하는 P1a 계획, 실행된 시험 로그, 남은 위험을 제출합니다. 큰 플랫폼 설계나 모든 기능 한 번에 구현은 요구하지 않습니다. 모델이 막히는 원인이 권한이면 권한 경계를 보고하고, 관련 없는 로컬 작업은 계속합니다.
