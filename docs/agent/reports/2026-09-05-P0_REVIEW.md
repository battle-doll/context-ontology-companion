# P0 설계 검토와 P1a 실행 기준

검토일 2026-09-05. 첫 결과물이며 전체 제품 완료 보고가 아니다.

## 판정

독립 제품 세 개와 최소 계약 우선 방향을 유지한다. 로컬 합성 자료를 사용하는 P1a 구현은 진행한다. 공개 노출, 실사용자 자료, 안정 계약 릴리스는 후속 gate의 실제 증거를 요구한다. 기존 Code 제품은 읽기 전용으로 보존한다.

## 현재 근거

- 인증된 GitHub 계정은 `battle-doll`. Code 공개 저장소 main의 실제 commit은 `be1699f784e48433a692bbfaa1c6c1d6f2b489b0`, README 제품 버전은 0.5.3이다. 공개 상태 설명은 현재 README 진술이며 Directory 상태를 이번에 직접 검증하지 않았다.
- 두 새 이름은 인증된 GET에서 404이고, 페이지 전체를 조회한 owner 저장소 목록에서도 발견되지 않았다. 생성 직전에 계정/동명 저장소/visibility/remote/branch를 재검사한다. 이번에는 원격 생성·push·공개·제출을 실행하지 않았다.
- 초기 작업 폴더는 Git 저장소가 아니었다. 제품별 로컬 `feat/p0-p1a` 저장소만 초기화했다. 기존 저장소를 복제하거나 변경하지 않았다.
- 기존 패키지 시험 32건 중 schema 관련 1건 skip, 참조 실험 20건 PASS. 필수 schema 검증은 의존성 부재로 실패했다. 로컬 격리 시험 환경에 정확한 버전의 검증 의존성을 준비해 재실행한다. 과거 PASS를 현재 결과로 쓰지 않는다.
- 기본 `/usr/bin/python3`는 3.9.6, 가용 번들 Python은 3.12.14. 새 제품은 Python 3.11 이상을 목표로 한다. macOS·Windows·Linux CI를 구성하되 실제 실행 여부를 구분한다.

## 반드시 수정할 사항

1. 기존 Context 전용 draft-0.1을 범용 계약으로 재명명하지 않는다. 새 최소 envelope와 `context-decision`, `code-reference` profile을 별도로 작성한다.
2. `user_asserted`, `source_observed`, `model_inferred`와 사용자 저장 승인을 독립 축으로 유지한다. 교환물의 assertion은 실행 권한을 발급하지 않는다.
3. P1a의 주체 주입/승인 adapter 시험과 실제 OAuth/호스트 사용자 인증을 구분한다. MCP에 apply/approve 도구나 approved boolean을 노출하지 않는다.
4. 필수 제약·충돌 양측·근거가 예산을 넘으면 부분 성공을 반환하지 않는다. known-at 미구현 입력은 명시적으로 거절한다.
5. 삭제는 본문, proposal, revision, 관계, 검색 결과와 내보내기에 함께 적용한다. 별도 파생 index/cache를 처음부터 만들지 않는다. 외부 백업·이미 내보낸 파일·SSD 물리 복구까지 지웠다고 주장하지 않는다.
6. Code의 stable ID와 co: vocabulary, runtime_unknown을 보존한다. 합성 Code mapping fixture는 실제 Code 제품 소비자 E2E를 대체하지 않는다.
7. OS 지원 정책과 호스트 지원을 분리한다. bash 전용 설치·POSIX 경로·chmod만으로 Windows 보안을 주장하지 않는다.
8. 영어 README와 ko/ja/zh-CN/ru README 및 언어별 docs 구조를 기존 Code와 맞춘다. 번역에서 기능·보안·출시 상태가 과장되지 않는지 검증한다.

## 현재 OpenAI 규격과 차이

[공식 패키징](https://developers.openai.com/plugins/build/plugins)은 `.codex-plugin/plugin.json`, skills, 선택적인 bundled `.mcp.json` 및 등록된 연결용 `.app.json`을 구분한다. 임의 parent/dependency/permission inheritance 필드를 만들지 않는다. 공개 앱 등록 ID는 실제 등록 전에 생성하거나 추측하지 않는다.

[공식 제출 절차](https://developers.openai.com/plugins/deploy/submission)는 Skills only와 With MCP를 지원한다. With MCP에는 실제 공개 서버 URL, domain verification, 정확한 annotations, 검증된 개발자 신원과 공개 정책/지원 문서가 필요하다. 로컬 stdio와 submission JSON만으로 공개 MCP 제출 요건을 충족하지 않는다. UI는 선택 사항이다. 제출·승인·게시를 각각 기록한다.

[공식 인증](https://developers.openai.com/plugins/build/auth)은 OAuth 사용자 인증, issuer/audience/expiry/scope 검증, resource metadata, PKCE S256 및 실제 선택한 CIMD/DCR 또는 사전 등록 client 구성을 요구한다. 로컬 주체 설정은 remote OAuth 증거가 아니다. 익명 Contracts 검증과 개인 Context 저장의 인증 요구를 분리한다.

[MCP 검토 기준](https://developers.openai.com/plugins/deploy/app-review)과 제출 문서에 따라 각 실제 도구에 readOnlyHint/destructiveHint/openWorldHint를 명시한다. 입력·출력 schema와 부작용이 일치해야 한다. widget이 없으면 CSP는 해당 없음이며, 허구의 CSP나 OAuth 설정을 생성하지 않는다. 제출 사례는 positive 5/negative 3을 준비하되 실행 여부를 별도 기록한다.

공식 HTML을 열어 확인했고 Markdown endpoint도 직접 GET했다. web 도구의 Markdown content-type 오류는 shell GET으로 보완했다. API key나 추가 LLM API는 이 제품 경로에 필요하지 않다.

## Tool surface 제안

Contracts: `validate_artifact`(형식·profile 의미), `check_compatibility`(정확한 방향/버전 쌍), `plan_migration`(손실·미지원 분석). 모두 순수 계산이며 입력 보관/원격 fetch/파일 쓰기 없음. 세 annotation은 true/false/false 순서(readOnly/destructive/openWorld). fact/auth 검증은 not_checked.

Context: `list_projects`, `search`, `fetch`, `get_context_history`, `build_context_pack`, `prepare_context_change`, `get_change_status`, `export_context`. prepare만 짧은 TTL의 private proposal을 쓰므로 readOnly=false이며 apply/delete 자체는 수행하지 않는다. 별도 인증된 검토 adapter만 승인·적용한다. 나머지는 응답 계산이며 파일 생성이나 payload 로그를 쓰지 않는다. 모든 metadata는 구현 완료 후 다시 대조한다.

## 저장소 디렉터리

각 제품은 독립 root에 README 5개, LICENSE/PRIVACY/SECURITY/SUPPORT/CONTRIBUTING/CHANGELOG, `.github/workflows`, `docs/{ko,ja,zh-CN,ru}`, `src`, `tests`, `examples`, `scripts`, `submission`, 제품별 상태 문서를 둔다. Contracts는 배포되는 versioned schema/profile과 validator를 소유한다. Context는 digest로 pin한 필요한 contract artifact를 vendor하고 별도 설치 의존을 만들지 않는다. `.codex-plugin`과 Skill/MCP 선언은 실제 실행 코드가 준비된 경우에만 추가한다.

## P1a 계획과 gate

1. 엄격한 JSON parse, 자원 제한, offline registry와 두 profile을 구현하고 adversarial fixture를 검증한다.
2. 주체·프로젝트 scope, valid time, provenance가 있는 합성 결정 proposal을 생성한다. 신뢰한 adapter 경계 밖에서 승인을 만들 수 없게 한다.
3. 승인과 저장을 한 transaction으로 적용하고 다른 process/session에서 근거를 포함해 정확히 복구한다.
4. 동일 idempotency key의 다른 내용, 만료·재사용 승인, stale revision, 교차 사용자/프로젝트 조회, 삭제 후 재검색·복구를 시험한다.
5. Context가 내보낸 자료를 Contracts가 직접 검증한다. 역방향 또는 미지원 버전은 성공으로 취급하지 않는다.
6. 단순 JSON 구조 검색을 기본선으로 유지한다. full graph를 추가할 근거가 없으면 추가하지 않는다. 모델 task benchmark와 token cost는 실제 계측 전 not_run.

P1b 정식 버전은 실제 소비자 시험과 독립 검토 후 결정한다. synthetic 테스트만으로 hosted-tested 또는 github-public-ready로 올리지 않는다.

## 주요 위험과 검증

승인 위조/재생 → adapter 전용 apply·digest·expiry·revision·transaction 시험. scope 누출 → 모든 read/write/export/관계 확장에 동일 주체 검사. 삭제 부활 → authoritative store 제거 및 tombstone, 새 세션 재검사. 시간 오류 → UTC/기간 역전·미지원 known-at 거절. provenance 과장 → 형식 PASS와 truth not_checked. 자원 고갈 → bytes/depth/list/string 제한. OS 차이 → 3-OS CI와 Windows ACL/경로/Unicode 시험. 공급망·공개 자료 → pin/hash, 합성 fixture, secret scan, license/지원 경로 확인.

독립 Architect는 별도 subagent context에서 검토한다. 구현자와 같은 모델인지 다른 모델인지 성능 비교를 주장하지 않는다. root는 Orchestrator와 한정된 Context 구현을 수행하며 설계 결론은 별도 Architect 검토를 참고한다. 관측 가능한 세부 모델·비용 수치는 unavailable로 기록한다.
