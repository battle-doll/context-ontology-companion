# 01. 제품 요구사항

## 문제와 사용자 가치

대화 요약만 저장하면 결정의 조건·근거·철회 여부가 희미해집니다. 코드만 분석하면 의도와 포기한 대안을 알기 어렵습니다. 이 제품은 프로젝트 결정의 근거를 찾고, 현재 유효한 조건만 새 작업에 제공하는 데 집중합니다.

개인별 일반 메모리 기능을 복제하기보다, **출처 연결·시점별 조회·명시적 대체·삭제·이식·코드 참조**를 제공하는 것이 차별화 가설입니다. 실제 사용자 효용은 P2 파일럿에서 검증합니다.

## MVP 사용자 흐름

1. “이 프로젝트에서는 배포 전에 회귀 테스트를 실행한다는 결정을 저장해 주세요.”
2. 호스트가 최소 문장, 프로젝트, 근거와 유효 시점을 제안합니다.
3. 사용자가 공유 범위와 내용을 확인하고 저장을 승인합니다.
4. 다른 세션에서 “이 프로젝트의 배포 조건을 찾아주세요.”라고 요청합니다.
5. 현재 유효한 결정과 근거, 대체 이력, 누락·충돌 여부를 반환합니다.
6. “이 결정을 변경/철회/삭제해 주세요.”는 별도 의미로 처리합니다.

첫 사용자 유형은 개발자·아키텍트·프로젝트 담당자입니다. 첫 공개 버전은 **개인 계정 소유 프로젝트**만 지원하고 조직 공동편집·개인 건강/금융 프로파일링은 포함하지 않습니다.

## 기능 요구사항과 수용 기준

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| FR-01 | 명시적 프로젝트 범위 | 읽기·쓰기·내보내기 전 서버가 소유권을 확인한다. |
| FR-02 | 승인 기반 저장 | 승인한 정규화 payload만 저장되고 승인 전 후보는 검색 결과에 나타나지 않는다. |
| FR-03 | 출처와 추출 방법 | 모든 활성 항목에 근거 참조가 있고 직접 진술·문서·모델 제안을 구별한다. |
| FR-04 | 유효 시점 | 미래·만료 항목은 현재 보기에서 제외되고 as-of 조회에서는 규칙대로 나타난다. |
| FR-05 | 수정과 대체 | 이전 revision을 덮어쓰지 않고 기대 revision 검증 후 대체한다. |
| FR-06 | 충돌 표현 | 서로 다른 조건·범위는 보존하고 실제 충돌은 사용자 판단 대상으로 표시한다. |
| FR-07 | 관련 문맥 검색 | 검색 결과에 ID·간단한 내용·출처·유효 상태를 제공한다. |
| FR-08 | bounded context pack | 관련 근거만 제한된 크기로 반환하고 생략·불확실성을 알린다. |
| FR-09 | 이력 조회 | 언제 무엇이 대체·철회됐는지 알 수 있으며 삭제 본문은 복원하지 않는다. |
| FR-10 | 실제 삭제 | 본문과 관리 중 파생물을 제거하고 처리 범위·잔여 백업 만료를 알린다. |
| FR-11 | 내보내기 | 명시적으로 선택한 프로젝트를 JSON/Markdown으로 내보낸다. RDF는 P4 확장이다. |
| FR-12 | 독립 사용 | Code Plugin이나 그래프 DB 없이 Context 제품이 동작한다. |
| FR-13 | 공개 호스트 연동 | 실제 지원 계정·표면에서 인증, 도구, 승인 흐름을 재현한다. |
| FR-14 | 선택적 코드 연결 | P4에서 승인된 portable 식별자만 연결하고 기존 분석기에 쓰지 않는다. |

## 비기능 요구사항

| ID | 요구사항 | 검증 방식 |
| --- | --- | --- |
| NFR-01 | 사용자·프로젝트 격리 | 교차 계정/프로젝트/페이지/캐시/내보내기 부정 시험 |
| NFR-02 | 재시도 안전 | 동일 idempotency key+payload는 동일 결과, 다른 payload는 충돌 |
| NFR-03 | 검증 가능성 | 출처 없는 근거를 만들지 않고 source unavailable을 표현 |
| NFR-04 | 경계 보존 | 기존 코드 플러그인 golden fixtures와 portable 계약 회귀 검증 |
| NFR-05 | 재현 가능한 배포 | 버전 고정, 체크섬, SBOM, 변경 이력, rollback 절차 |
| NFR-06 | 관측성과 최소 로그 | 지식 본문 없이 오류·지연·권한·삭제 완료를 검증 |
| NFR-07 | 접근 가능한 승인 | 키보드·화면읽기 지원, 대안 텍스트, 모바일/웹 실제 시험 |
| NFR-08 | 사용량 제한 | 요청 크기·건수·그래프 깊이·검색 시간·보존·계정 quota 제한 |

## 제외 범위

전체 ChatGPT 기록 수집, 플랫폼 메모리 API 우회, 대화 감시 데몬, 사용자 미승인 자동 프로파일링, 타인 자료 권한 우회, 고객사 코드 업로드, 실행 가능한 기억, 의료/결제/신원/인증 비밀 보관, 자율 거래·배포·메일 발송은 제외합니다.

원본 전체 저장, 벡터 DB, 별도 그래프 DB, 3D 시각화, 팀 멀티테넌시, 다수 호스트용 자동 Hook은 MVP 선행 조건이 아닙니다.

## 숫자 목표의 상태

검색 적중률·지연·토큰 예산은 [평가 설계](08_TEST_AND_EVALUATION.md)의 **제안 통과 기준**입니다. 실측 수치나 사용자에게 보장하는 SLA로 홍보하지 않습니다.

## v2 추가 요구사항

| ID | 요구사항 |

| FR-19 | 같은 정보·예산의 단순 기억 기준선과 작업 재개 결과를 비교한다. |
| FR-20 | 스키마/플러그인/제품/검증기 버전과 완료 상태를 구분한다. |
