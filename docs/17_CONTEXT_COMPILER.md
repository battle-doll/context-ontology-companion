# 17. 문맥 재구성기 — Context Compiler

상태: 구현 전 계약·불변식. `experiments/`는 일부 불변식의 참조 실험입니다.

## 책임

검색 결과를 길게 요약하는 것과, 지금의 작업에 필요한 유효한 문맥을 구성하는 것을 구분합니다. 재구성기는 인증된 프로젝트·조회 시점·질문·예산을 받아 **근거·충돌·누락 상태를 포함한 한정된 문맥 팩**을 만듭니다.

플러그인이 ChatGPT 시스템 메시지를 바꾸거나 새 대화에서 자동 호출된다는 전제는 없습니다. 허용된 호출 시 반환되는 데이터이며, 호스트가 실제 사용 여부를 결정합니다.

## 경로

```text
인증/현재 권한 확인
→ 프로젝트·환경·시점 확정
→ 목표와 적용 중인 제약의 권위 있는 조회
→ 관련 결정/작업의 구조화·키워드 검색
→ 제한된 그래프 확장
→ 삭제·권한·시점 재확인
→ 근거 묶음/충돌 그룹 생성
→ 필수 그룹 예산 검사
→ 선택 그룹 배치
→ 최종 직렬화 크기 검사 + 누락/커버리지 보고
```

중요 제약은 유사도 검색 Top-K에만 의존하지 않습니다. 프로젝트에 적용되는 현재 제약을 별도 조회해 필수 집합의 후보로 만듭니다. 필수 판정의 근거와 정책 버전도 기록합니다. 그래프 확장과 필수 판정은 서로 다른 책임입니다.

## 출력 의미

실제 최종 스키마는 P1 소비자 시험 후 정합니다. 최소 의미는 다음과 같습니다.

| 필드 | 의미 |
| --- | --- |
| `snapshot_id` | 출력 생성에 사용한 일관된 데이터 스냅샷 |
| `scope` | 서버가 확인한 프로젝트/환경; 모델 임의 tenant 값은 권한이 아님 |
| `valid_at` | 사실/결정이 적용되는 시점 |
| `known_at` | 당시 시스템이 알고 있던 정보 기준; 지원하지 않으면 기능 자체를 거절 |
| `claims` | 선택한 주장과 리비전; 각 주장에 최소 근거 |
| `conflict_groups` | 하나만 남기면 오해가 생기는 주장 집합 |
| `coverage` | 필수 포함 여부, 선택 누락, 검색 한계; 전체 원본을 다 안다는 뜻이 아님 |
| `budget` | 실제 측정 단위, 한도, 직렬화 크기; 토큰 측정이면 tokenizer 식별자 |
| `use_constraints` | 외부 지식은 비신뢰 데이터이며 실행 승인으로 사용하지 않음 |

## 예산 불변식

I-01. 적용 중인 중요 제약과 목표를 임의 요약/절단해 의미를 바꾸지 않습니다.

I-02. 포함된 주장은 근거 참조와 함께 들어갑니다. 내용만 남기고 provenance를 제거하지 않습니다.

I-03. 해결되지 않은 충돌 집합은 양측 이상을 함께 포함하거나 집합 전체를 누락/미해결로 표시합니다. 한쪽만 보내 확정 사실처럼 만들지 않습니다.

I-04. 필수 그룹 전체가 예산에 들어가지 않으면 `insufficient_budget` 계열 상태로 작업을 중단/축소합니다. 성공 팩처럼 가장하지 않습니다. 오류 자체조차 예산을 넘으면 내부 오류 코드만 호출 계층에 반환하고 호스트가 별도로 처리합니다.

I-05. 필수가 모두 들어가더라도 선택 항목이 누락됐으면 부분 커버리지를 표시합니다. 후보 집합의 완전성과 전체 지식의 완전성은 다릅니다.

I-06. JSON 전체의 실제 직렬화 크기를 계산합니다. 한글 문자 수와 토큰 수를 환산해 정확하다고 주장하지 않습니다. 토큰은 실제 tokenizer를 주입할 수 있을 때만 같은 단위로 측정합니다. 이 실험은 UTF-8 bytes를 사용합니다.

I-07. 같은 입력·정책·버전·측정 함수에는 결정론적인 결과를 만듭니다. 키 정렬과 동률 우선순위를 고정합니다. 이 성질은 정보의 사실 정확성을 의미하지 않습니다.

I-08. 새 요청마다 현재 권한과 삭제 상태를 다시 검사합니다. 예전 문맥 팩을 읽을 수 있었다는 이유로 현재도 허용하지 않습니다. 캐시 key에는 권한/삭제 epoch 또는 동등한 무효화 증거를 포함합니다.

## 시간 의미

`valid_from/valid_until`은 적용 기간이고 `recorded_at`은 기록 시점입니다. `recorded_at` 하나와 현재 status만으로 과거의 known-at 상태를 정확히 재구성했다고 주장하면 안 됩니다.

첫 MVP는 **현재 알고 있는 자료 기준의 현재/적용 시점 조회**를 명확히 지원합니다. 과거 `known_at` 기능은 immutable revision/event history, 삭제 처리, 수정 취소, 당시 승인 상태를 재구성하는 시험을 통과한 뒤 노출합니다. 지원 전에는 known_at 값을 조용히 무시하거나 현재 자료를 반환하지 않습니다. 삭제된 본문은 역사 질의에서도 복원하지 않습니다.

`superseded` 표시만 보고 과거 적용 시점의 올바른 결정을 무조건 버리지 않습니다. 어떤 질의 축을 지원하는지 명시하고, 승인된 대체 관계와 유효기간에 따라 선택합니다.

## 예시

프로젝트의 기존 운영 정책을 유지해야 한다는 필수 제약, 이 정책을 바꿀지 아직 논의 중인 두 대안, 근거 문서가 있다고 가정합니다. 예산이 작다고 변경 찬성 의견만 남기면 에이전트가 이미 변경이 승인된 것으로 오해할 수 있습니다. 따라서 제약과 승인 상태는 유지하고, 대안은 한 묶음으로 다루며, 충분하지 않으면 구체적으로 범위를 줄입니다.

## 참조 실험의 경계

`experiments/context_pack_reference.py`는 위 과정 중 마지막 예산 선택만 수행합니다. 입력이 이미 허용된 것인지 확인하지 않으며, 시간·권한·근거의 진실성·충돌 탐지를 구현하지 않습니다. 입력은 합성 자료에만 사용합니다. 제품 인증 계층이나 완성된 검색기로 사용하지 않습니다.
