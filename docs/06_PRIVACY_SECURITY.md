# 06. 개인정보·보안 설계

이 문서는 제품 요구사항이며, 구현 완료 또는 법률 준수 보증이 아닙니다. 공개 정책 문서는 실제 운영·보존·수탁 처리에 맞춰 소유자가 검토해야 합니다.

## 최소 수집

첫 버전은 프로젝트 결정/목표/요구사항/제약과 해당 작업의 짧은 근거만 받습니다. 전체 채팅 로그, 의료 기록, 결제 카드 데이터, 정부 식별자, 비밀번호·토큰·OTP는 받지 않습니다. 업로드 전 안내, 입력 검증, 제한된 출력, 본문 없는 로그를 함께 사용합니다. 필터가 모든 민감정보를 찾아낸다고 보장하지 않습니다. [S-02](13_SOURCES_AND_VERIFICATION.md)

대화 전체를 외부에 보낸 뒤 필터링하는 방식은 최소 수집이 아닙니다. 초기 MVP에서 일반 문서 대량 업로드를 제외하는 이유도 이에 있습니다.

## 접근 제어

공개 서비스는 개인별 인증이 필수입니다. 권한은 토큰 issuer/audience/expiry/scopes와 프로젝트 소유권을 확인해 결정합니다. MCP 연결 계정이 현재 브라우저 승인 계정과 일치하는지도 확인합니다. 관리·삭제 기능은 사용자 소유 범위에 한정하며 조직 공유는 별도 설계 이후 도입합니다.

인증 토큰은 Git, 모델 입력, 에러 메시지, trace에 넣지 않습니다. 임시 승인 링크에는 비밀 토큰이 아니라 불투명 proposal ID만 사용하고, 실제 작업은 인증된 사용자 세션에서 수행합니다.

## 데이터 보존 제안 — 소유자 확정 필요

| 데이터 | 초안 기본값 | 주의 |
| --- | --- | --- |
| 미승인 proposal | 최대 15분 | 만료 시 payload 제거 |
| 승인된 context | 사용자 삭제 또는 명시된 보존 기간까지 | 무기한·무제한 저장 약속 금지 |
| 철회/대체 이력 | 프로젝트의 동의한 보존 정책 | 삭제 요청은 이력 본문에도 적용 |
| 검색 캐시 | 짧은 TTL | 삭제·권한변경 즉시 무효화 |
| 보안 운영 로그 | 30일 제안 | 본문·excerpt·credential 금지 |
| 관리 백업 | 30일 이내 만료 제안 | 실제 서비스의 설정/복구 시험 필요 |

값은 운영 약속이 아닙니다. 출시 전에 배포 환경의 실제 동작과 일치시키고 정책에 공개해야 합니다.

## 삭제 설계

삭제 대상은 record, revision payload, excerpt, relations의 민감 label, 검색 문서, embedding, 캐시, 미승인 draft, 관리하는 export와 복제본입니다. 이미 사용자가 내려받았거나 외부에 게시한 사본을 이 서비스가 회수할 수 있다고 말하지 않습니다.

삭제 응답은 단계를 구분합니다: 접근 차단 완료, 주 저장소/파생물 제거 완료, 백업 만료 대기, 최종 처리 범위. 삭제 원장에는 최소 불투명 ID·시각·처리 상태만 두며 원문 digest만으로 낮은 엔트로피 개인정보를 복원·대조할 위험도 검토합니다.

“불변 로그”를 이유로 본문을 영구 보존하지 않습니다. 변경 이력과 삭제 가능 payload를 분리하고, 백업 복구 시 삭제 원장을 재적용한 뒤 서비스에 연결합니다. 암호화 키 폐기를 물리 삭제와 동일한 보장으로 홍보하지 않습니다.

## 로그·관측성

request class, 응답 시간, 오류 코드, 권한 거절, 삭제 단계, 모델 호출 유무·비용 계측 가능 여부를 기록합니다. 인증 또는 사용자 식별을 위해 꼭 필요한 내부 운영 식별자는 접근 제한하고 공개 tool 결과로 내보내지 않습니다.

개발 보고서는 실제 수행 사실을 기록하되 비공개 사고 과정, 실제 사용자 대화, 인증 비밀을 포함하지 않습니다.

## 공개 전 필수 검토

개인정보 처리방침, 약관, 지원 채널, 운영자 신원, 수탁자, 보관 위치, 보존·삭제, 사고 대응은 실제 운영 상태로 작성합니다. 법률 준수 판단이나 확인되지 않은 인증을 AI가 대신 확약하지 않습니다.
