# 16. 재평가 — 모델 교체가 아니라 제품·실행 기준 개선

2026-09-05 · 기존 설계 0.1.0-draft.1 → 수정 설계 0.2.0-draft.1

## 판단

별도 Code/Context 제품, 계약 우선, 재사용 입증 후 공통 순수 코어 추출은 유지합니다. 기존 설계에는 승인·출처·시점·삭제·사용자 격리·실제 완료 상태 구분이 이미 들어 있습니다. 이를 이번에 새로 발견한 설계처럼 포장하지 않습니다.

다만 **공통 계약 라이브러리와 공개 플러그인을 혼동한 점**, **공통이라고 부르기에는 Context에 묶인 스키마**, **저장/검색 성공과 작업 재개 성공 사이의 검증 공백**을 수정해야 합니다.

## 근거 범위

원본 ZIP 57개 파일을 회수해 검사하고 기존 시험 32건을 재실행했습니다. 현재 Code 저장소의 README를 읽고 공식 OpenAI 모델/플러그인 문서를 확인했습니다. 실제 서버, 사용자 DB, Codex 앱 또는 별도 Sol/Astra 런타임을 비교 시험하지 않았습니다. 모델 간 이 프로젝트 성능 향상률은 미측정입니다.

F-02는 기존 Context 스키마의 문법 오류라는 뜻이 아닙니다. **범용 계약으로 재사용하려는 의도와 현재 정의가 다르다**는 설계 문제입니다. 원본 스키마를 몰래 새 의미로 바꾸지 않습니다.

## 유지할 좋은 결정

출처와 내용의 진실성을 구분합니다. 사용자 승인과 AI 추론은 별개의 축입니다. 원문 전체를 수집하지 않고 목적에 필요한 승인 문맥만 보관합니다. 삭제는 본문과 파생 자료까지 포함하며, 감사 이력에 삭제된 내용을 되살리지 않습니다. 승인 토큰은 사용자·대상·리비전·payload·만료에 묶습니다. 검색 전후 ACL 검사를 유지합니다. 추가 LLM 서버 호출은 기본 경로에 없습니다.

원본에는 인증/호스트 UX 조기 검토, 한 서비스로 시작, 선택적 벡터 검색, 오케스트레이터/설계자 분리도 이미 있었습니다. 이번 변경은 이를 없애거나 새로 추가한 것처럼 주장하지 않습니다.

## Astra Pro를 어디에 사용하는가

모델 이름을 제품 필수 의존성으로 넣지 않습니다. 복잡한 계약 충돌, 근거 부족, 삭제/동시성 실패, 호스트 승인 설계에 대한 설계·반례 검토 역할에 우선 배치합니다. 반복 변환·문서 링크·스키마·타입·단위 시험은 결정론적 도구가 수행합니다. 모델 교체로 도구 접근권한이나 저장 승인 권한이 증가하지 않습니다.

모든 역할을 Astra로 고정하지 않습니다. 실제 사용 가능한 모델과 평가 결과로 배치하며, 같은 모델/같은 에이전트의 재검토를 독립 검증이라고 기록하지 않습니다. [실행 프로필](19_MODEL_EXECUTION_PROFILE.md)

## 제품 가치의 새 기준

“더 많이 기억한다”보다 “새 세션에서 이전 결정을 근거와 함께 복구하고, 현시점의 제약을 어기지 않고 다음 작업을 이어갈 수 있다”를 검증합니다. 단순 Markdown/JSON 검색으로 같은 성능이 나오면 그래프 복잡성을 늘리지 않습니다. [평가 프로토콜](18_EVAL_PROTOCOL.md)

## 이번 수정의 한계

이 개선판도 개발 설계입니다. 참조 실험은 사전에 허용되고 시점 선택이 끝난 후보 그룹의 예산·원자성만 다룹니다. 실제 권한, 검색 누락, DB 동시성, 삭제 보장, 모델의 작업 성공을 검증하지 않았습니다. 제품의 공개 심사 승인도 보장하지 않습니다.
