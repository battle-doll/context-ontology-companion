# 04. 문맥 생명주기와 검색·복구

## 수집·승인·저장

```text
사용자의 명시적 저장 요청
 -> 최소 문장과 공유 범위 설명
 -> bounded candidate 준비 (서버 전송 자체도 공개)
 -> 서버 검증 및 짧은 수명의 pending proposal
 -> 사용자에게 정규화된 최종 내용·출처·시점 표시
 -> 인증된 실제 사용자 승인
 -> 일관된 transaction / revision / idempotency 결과
 -> 검색 가능한 current projection
```

모든 대화를 수집한 뒤 중요도를 판단하는 방식은 사용하지 않습니다. 공개 플러그인의 정상 입력은 해당 작업에 필요한 명시적인 snippet 또는 선택한 리소스입니다. [S-02](13_SOURCES_AND_VERIFICATION.md)

최초 MVP는 단일 작업 proposal을 기본으로 합니다. 초안 보관 TTL은 15분 제안이며 P0에서 확정합니다. TTL 만료 시 본문을 지우고 공개 검색에 노출하지 않습니다. 승인 전에도 서버로 전달된다는 사실을 UI/정책에 설명합니다.

## 저장·대체·철회·삭제의 구분

| 동작 | 의미 | 과거 본문 |
| --- | --- | --- |
| create | 새 승인 문맥 추가 | 존재 |
| supersede | 새 결정이 이전 결정을 특정 시점부터 대체 | 동의한 보존 정책 내 이력으로 보관 |
| retract | 더 이상 유효하다고 취급하지 않음 | 철회된 이력으로 보관 가능 |
| erase | 관리 중인 해당 내용 및 파생물 제거 | 보존하지 않음, 백업 처리 한계 설명 |

사용자가 “잊어줘/삭제해줘”라고 하면 단순 retract로 대신 처리하지 않습니다. 삭제 범위가 모호하면 정확한 대상만 식별하고 확인합니다.

## 충돌과 변경

같은 subject/predicate라도 프로젝트, 환경, 버전, 적용 기간이 다르면 공존할 수 있습니다. 예컨대 테스트 환경의 정책과 운영 환경의 정책은 자동 충돌이 아닙니다. 진짜 충돌 후보도 최신 문장이 무조건 승리하지 않습니다.

사용자가 대체를 승인하면 이전 record가 연결된 revision으로 남고 현재 투영에는 새 기록이 나타납니다. 기존 대안과 포기 이유를 저장할 때도 주장과 관찰, 검토 결론을 분리합니다.

## 검색 파이프라인

1. 인증·프로젝트 권한과 요청 범위를 먼저 결정합니다.
2. 정형 조건, 선택한 시점, 요청 의도를 해석합니다.
3. 전문/부분 문자열·alias 검색으로 후보를 좁힙니다.
4. 같은 권한 경계 안에서 최대 2-hop 관계를 확장합니다.
5. authoritative store에서 삭제·철회·유효시간·권한을 다시 검사합니다.
6. 출처 적합성, 조건 일치, 검토 상태와 관련도로 순위를 정합니다.
7. 중복을 제거하고 근거를 포함한 bounded context pack을 반환합니다.

벡터 검색은 옵션입니다. 한국어 패러프레이즈 평가에서 baseline 대비 향상이 입증되고 비용·외부 처리·삭제 요건이 충족될 때 도입합니다. 임베딩은 사실의 신뢰도나 사용자 권한을 결정하지 않습니다.

## Context pack

기본 구성: 현재 목표, 승인된 제약, 관련 결정, 진행 상태, 필요한 근거, 충돌/누락, 다음에 확인할 항목입니다. 매번 전체 프로젝트 기록을 주입하지 않습니다.

하드 한도는 반환 문자 수와 item 수로 강제합니다. 토큰 수는 실제 tokenizer를 사용할 때만 정확한 값으로 표현하고, 그렇지 않으면 추정치라고 표기합니다. MVP 기본 상한 제안은 12,000자/20개 기록이며 더 큰 결과는 명시적 페이지 조회로 분리합니다. 이것은 모델 컨텍스트 용량 보장이 아닙니다.

근거가 없는 공간을 그럴듯한 설명으로 채우지 않습니다. 단편 근거만 있는 경우 “이 source에 이렇게 기록되어 있음”으로 답하고, 현재 사실을 검증한 것과 구분합니다.

## 세션 재개

새 세션은 사용자 또는 지원되는 호스트 지침에 의해 관련 프로젝트를 선택하고 context pack을 조회합니다. 제품은 호스트의 모든 세션 시작/압축 이벤트를 볼 수 있다고 가정하지 않습니다.

Codex 로컬 Hook은 실제 버전·권한·이벤트 지원이 검증된 경우에만 별도 어댑터로 추가합니다. ChatGPT 웹에 같은 Hook이 존재한다고 주장하지 않습니다. 자동 호출이 제공되지 않으면 명시적 “이 프로젝트 이어서 작업” 요청이 기본 동작입니다.

## 출처 변경·접근 상실

원문이 수정·삭제되거나 접근권한이 사라지면 provenance 상태를 갱신합니다. 기존 기록이 복사 저장본인지 참조뿐인지 표시하고, 새로운 권한 없이 재수집하지 않습니다. 가져오기 source ID와 payload digest만으로 영구적인 원문 접근권한을 만들지 않습니다.
